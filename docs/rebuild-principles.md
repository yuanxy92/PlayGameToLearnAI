# 重建原则

## 本次归零范围

以下内容不再保留：

- 旧 HTML 页面。
- 旧 JavaScript 运行代码。
- Phaser / RexUI 等旧技术尝试。
- 旧 UI layout。
- 旧生成素材和截图。
- 旧构建配置和依赖。

仓库现在只保留设计文档。

## 后续重建前必须先确定

1. 目标平台：浏览器 H5、微信小游戏、普通小程序、快应用，或其他。
2. 固定虚拟分辨率：建议仍采用固定游戏画布，只做整体缩放。
3. UI 方案：先设计完整交互稿，再写代码。
4. 美术方案：先定地图、关卡、元件、反馈的视觉语言，再生产素材。
5. 架构方案：把“课程数据 / 玩法规则 / 渲染表现 / 平台适配”分层。

## 建议的新架构层次

```text
design/
  关卡、剧情、学习目标

core/
  纯规则：输入、管道、泵站、输出、通关判定

renderer/
  画面表现：地图、关卡、动画、反馈

platform/
  平台适配：H5、微信小游戏、小程序壳、存档
```

这四层不要再混在一个文件里。

## 第一阶段目标

不要急着做完整游戏。先做一个极小垂直切片：

- 首页。
- 地图。
- 第 1 关。
- 通关弹窗。
- 公式总结入口。

只有当这 5 个页面在手机尺寸下完全稳定，再扩展第 2 到第 7 关。
